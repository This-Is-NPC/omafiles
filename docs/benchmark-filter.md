## Interpretation and limitations


The apparent primary 1M startup loss did not reproduce with the order reversed: after first frame is approximately 5.5 ms faster in A and 5.4 ms faster in B; settle is approximately 3.8 ms faster in A and 0.4 ms slower in B. Raw settle ranges overlap. Relocation-normalized disassembly also confirms identical instruction sequences in all 11 enumeration/sort functions in the two executables, and unfiltered empty-index startup takes the existing compact-range return before matcher creation or scanning. This supports run/batch variation rather than a consistent added startup cost; it does not erase the original increases or prove a universal timing bound.

Small-folder settle has two overlapping modes in both products (approximately 635–680 ms and 750–785 ms). Changes in how many of five runs land in each mode move medians by approximately 100–120 ms in either direction. Other positive medians are kept in the tables: small-folder filtering, sub-millisecond scrolling changes, first-frame spread, RSS variation and image phases. Their raw values overlap and do not establish a consistent product regression in this sample. The data do not justify claiming an improvement for every metric.


Full event/sample/host-load/cgroup evidence and validity checks: Omakiten task 3350 and `/tmp/omafiles-3350/{before,after,before-1m-check,after-1m-check}.json`; the full report is attached through task comments. This document retains all primary metric medians and raw arrays plus the countercheck arrays so the conclusion can be reviewed without those temporary files.
